# 管理员命令

管理员命令主要用于运维和管理。`/silence`、`/清除订阅` 群内也可用（master 起，需 BOT 管理员或 BOT 群管理员）；`/刷新`（`/scan`）、`/重新订阅` 群内也可用（`[next-dev]`，需 BOT 管理员或 BOT 群管理员）。其余**只能私聊使用**；其中 `/ping` 不要求任何权限，`/whosyourdaddy` 仅在 BOT 没有管理员时可用，其余要求 BOT 管理员。

!!! tip "和 Web 管理面板的区别"
    `[next-dev]` 的 [Web 管理面板](../deploy/webui.md) 能图形化完成大部分管理操作（管理员、群管理员、沉默模式、黑名单、命令开关等），与这里的聊天命令是两套入口，管理的是同一份数据。

---

## `/whosyourdaddy` - 设置管理员

| 默认权限 |
|---------|
| 无（仅 BOT 没有管理员时） |

用于初次启动设置管理员。成功后发送命令的账号成为 BOT 管理员。

```
/whosyourdaddy
```

!!! warning "仅首次有效"
    只有 BOT 没有管理员时此命令才生效，后续再发无效。

如需离线设置或更换管理员，见 [首次配置](../deploy/first-config.md)。

---

## `/sysinfo` - 查看 BOT 信息

查询 BOT 当前好友数、群组数、订阅数量。

```
/sysinfo
```

返回示例（订阅源顺序取决于注册顺序，各订阅源之间有空行）：

```
当前好友数：88
当前群组数：84
当前bilibili订阅数：207

当前douyu订阅数：2

当前youtube订阅数：28

当前huya订阅数：1
```

`[next]` 起还提供内容等价的 `/status` 命令。

---

## `/ping` - 测试连通

```
/ping
```

返回：

```
pong
```

用于快速验证 BOT 是否正常响应。

## `/log` - 查询日志

临时查看 BOT 日志。日志按天保存在 `logs/YYYY-MM-DD.log`，不指定条数时默认 10 条，不指定日期时默认当天。

```
/log [条数] [-d YYYY-MM-DD] [-k 关键字]
```

### 例子

查看最近 10 条日志：

```
/log 10
```

查看含 `error` 关键字的最近 20 条（先按关键字过滤，再按条数过滤）：

```
/log 20 -k error
```

查看 2026-01-02 的日志（需要日志文件仍在保留期内，默认保留 7 天）：

```
/log 20 -d 2026-01-02
```

## `/block` - 拉黑/解封

| 默认权限 |
|---------|
| BOT 管理员 |

把某个 QQ 号或 QQ 群加入黑名单，被拉黑的对象发来的命令会被直接忽略：

```
/block <QQ号或群号> [天数] [-d]
```

- 不填天数表示**永久**拉黑
- 加 `-d` 表示解除拉黑

### 例子

永久拉黑 QQ 10000：

```
/block 10000
```

拉黑群 123456 七天：

```
/block 123456 7
```

解除拉黑：

```
/block 10000 -d
```

!!! note "不能拉黑自己"
    目标不能是发送命令的账号本身。

## `/quit` - 退出群聊

退出群聊，或清除未正常退出的群的数据。

```
/quit <群号> [-f]
```

### 例子

退出群 123456（若 BOT 不在群内则无效果）：

```
/quit 123456
```

退出并**强制清除数据库内该群的数据**（不管 BOT 是否在群内）：

```
/quit 123456 -f
```

!!! tip "何时用 -f"
    强制清除用于维护数据库，当退群事件没正常触发时（如群被封、BOT 掉线期间被踢），BOT 侧仍留存该群的数据。`-f` 不依赖 BOT 是否还在群内。

## `/mode` - 设置运行模式

| 模式 | 好友申请 | 加群邀请 |
|------|---------|---------|
| `公开` | 自动同意 | 自动同意 |
| `私人` | 自动拒绝 | 自动拒绝 |
| `审核` | 保留待审 | 保留待审 |

### 例子

查看当前模式：

```
/mode
```

切换到私人模式：

```
/mode 私人
```

切换到审核模式：

```
/mode 审核
```

切换回公开模式：

```
/mode 公开
```

!!! note "审核模式"
    审核模式下用 `/好友申请` 和 `/群邀请` 命令管理待审请求。

!!! note "加群邀请的例外"
    无论当前是什么模式，如果发起加群邀请的人是 BOT 管理员，BOT 都会直接同意。

---

## `/好友申请` - 管理好友申请

审核模式下管理好友申请。

```
/好友申请                          # 查看当前申请
/好友申请 <ID>                     # 同意指定申请
/好友申请 --reject <ID>            # 拒绝指定申请
/好友申请 --all                    # 同意全部
/好友申请 --all --reject           # 拒绝全部
```

申请 ID 会在查看申请时展示。

---

## `/群邀请` - 管理群邀请

审核模式下管理群邀请，用法与 `/好友申请` 大致相同，但拒绝时可以附上理由：

```
/群邀请                            # 查看
/群邀请 <ID>                       # 同意
/群邀请 <ID> --reject              # 拒绝
/群邀请 <ID> --reject 拒绝理由      # 拒绝并附上理由
/群邀请 --all                      # 同意全部
/群邀请 --all --reject             # 拒绝全部（不能附理由）
```

拒绝理由只能跟在 `<ID>` 之后；`--all --reject` 不接受理由参数。

---

## `/silence` - 沉默模式

管理员私聊可设置全局或指定群的沉默模式：

```
/silence                  # 全局开启
/silence -g 123456        # 对群 123456 开启
/silence -d               # 全局关闭
/silence -d -g 123456     # 关闭群 123456
```

详见 [权限命令 - silence](permission.md)。

## `/admin` - 查看管理员

```
/admin
```

显示所有拥有 Admin 权限的人。

## `/检测异常订阅` - 检查异常订阅

| 默认权限 |
|---------|
| BOT 管理员 |

由于一些情况无法正常退出 Q 群（群被封、BOT 离线期间被踢），BOT 会向不存在的群推送，增加不稳定。

此命令查询是否存在「有订阅但 BOT 不在群内」的情况：

```
/检测异常订阅
```

---

## `/清除订阅` - 清除订阅

| 默认权限 |
|---------|
| BOT 管理员 |

清除异常订阅，或清除指定群的订阅，可指定网站和种类。

!!! danger "清除订阅无法撤销"
    清除后需重新订阅。

### 例子

清除异常订阅：

```
/清除订阅 --abnormal
```

清除异常的 bilibili 订阅：

```
/清除订阅 --abnormal --site bilibili
```

清除异常的 bilibili 直播订阅：

```
/清除订阅 --abnormal --site bilibili --type live
```

清除异常的直播订阅（所有网站）：

```
/清除订阅 --abnormal --type live
```

清除群 123456 和 223456 的订阅：

```
/清除订阅 -g 123456,223456
```

清除指定群的 bilibili 直播订阅：

```
/清除订阅 -g 123456,223456 --site bilibili --type live
```

!!! note "群内用法"
    群内使用 `/清除订阅` 时只针对当前群，且只有 `--site`、`--type` 两个选项（没有 `--abnormal` 和 `-g`）。

## `/重新订阅` - 微博一键重新订阅（`[next-dev]`）

| 默认权限 | 使用位置 |
|---------|---------|
| BOT 管理员（私聊）/ BOT 管理员或 BOT 群管理员（群内） | 私聊需 `-g`，群内直接发 |

微博 Cookie/SUB 失效后，用该命令按本地订阅记录重新拉取订阅信息：

```
/重新订阅 -g <群号>     # 私聊指定群
/重新订阅               # 群内直接对当前群
```

!!! note "私聊必须指定群"
    私聊版本的 `-g <群号>` 是必填参数，且只对当前群内已订阅的微博用户生效。

---

## `/wb登陆` - 微博扫码登录（`[next-dev]`）

| 默认权限 | 使用位置 |
|---------|---------|
| BOT 管理员 | 私聊 |

启动微博扫码登录，BOT 会私聊发送二维码，用微博 APP 扫码后 SUB 会写入配置并尽量立即生效：

```
/wb登陆
```

!!! warning "需要开启 qrlogin"
    需先在 `application.yaml` 中设置 `weibo.qrlogin: true`，否则命令会提示未启用。

扫码成功后 SUB **先写入配置文件、再加载到内存**，进程内立即切到 `login` 模式，不需要重启。详见[微博订阅](../sources/weibo.md)的模式说明。

---

## `/刷新`（别名 `/scan`）- 手动刷新推特订阅（`[next-dev]`）

| 默认权限 | 默认启用 | 可禁用 | 使用位置 |
|---------|---------|--------|---------|
| BOT 群管理员 / BOT 管理员 | 是 | 是 | 群内 |

在**群内**手动触发本群 Twitter 订阅的强制刷新，立即拉取最新推文（平时由轮询自动刷新）：

```
/刷新
/scan
```

`/刷新` 与 `/scan` 执行等价。但启用/禁用只认 `刷新`（用 `/enable 刷新`、`/disable 刷新`）：`/disable scan` 会提示成功，实际不会禁用该命令，因为执行前的禁用检查固定用 `刷新`。

---

## `/disable --global` 与 `/enable --global` - 全局启停命令

全局控制命令的启停，对所有群生效。

```
/disable --global <命令>     # 全局禁用
/enable --global <命令>      # 全局启用
```

### 例子

全局禁用 help：

```
/disable --global help
```

全局禁用 watch：

```
/disable --global watch
```

全局启用 watch：

```
/enable --global watch
```

!!! note "不覆盖单群设置"
    全局禁用后所有群都不能用；再次全局启用时，恢复各群原有设置（A 群禁用、B 群启用各自保留）。

---

## `/退订更新` - 关闭更新通知

DDBOT 每 24 小时检查一次新版本，有更新会私聊通知管理员。不想接收可关闭：

```
/退订更新          # 关闭更新通知
/退订更新 -d       # 恢复接收
```
