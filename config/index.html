    配置总览

    DDBOT-WSa 的配置文件是 application.yaml，首次运行会在当前工作目录自动生成一份示例配置（源码里的 exampleConfig）。

    生成文件包含哪些段

    不同分支生成的文件不一样：

    • master：bot、bilibili、twitter、douyin、concern、template、autoreply、customCommandPrefix、logLevel、websocket、reloadDelay。
    • [next] 追加：acfun、weibo、youtube、twitcasting、extDb、telegram。
    • [next-dev] 追加：proxy、localProxyPool、pyProxyPool、imagePool、loliconPool、localPool、douyu、huya、xhs、twitch、heybox、notify、dispatch、cronjob、debug、message-marker、qq-logs、adapter、admin；同时移除 reloadDelay。

    下面这份 YAML 是字段速查 / 合并示例，不是生成文件的全集。生成文件里没有的键，需要时手动添加；它们是否被读取见各子页面。

    配置文件位置

    • 路径：DDBOT 当前工作目录下的 application.yaml
    • 程序启动时只检查当前目录的 application.yaml；不存在就先在当前目录写一份，然后才依次 AddConfigPath(".")、AddConfigPath("./config") 读取。当前目录总有一份且排在前面，所以放在 ./config/application.yaml 的配置不会被读到
    • 修改后部分配置支持热重载（如 customCommandPrefix、cronjob；[next-dev] 的 platform.<site>.enable），其余需重启

    YAML 格式

    • 删除 # 及后面的注释
    • 冒号后必须有一个英文空格
    • 所有标点用英文半角
    • 格式错误会导致启动闪退

    [next-dev] 启动时会按行校对一遍配置，把「看起来写了、其实读不到」的问题带行号写进日志（只警告、不中断启动）：全角冒号当键分隔符、同一层里大小写不同或重复的键、用 Tab 缩进。照着日志改即可。

    已失效 / 需注意的字段

    • bot.account / bot.password：不在自动生成的配置里，QQ 连接由 OneBot 实现端负责。[next-dev] 起代码完全不读取；master / next 只有内置 MiraiGo 初始化会读到（bot/bot/bot.go），而登录调用已停用（根 bot.go 里 bot.Login() 被注释），填了不起作用。
    • sendFailureReminder.enable / .times：master / next 有效，发送累计失败达到 times 次触发 notify.bot.send_failed.tmpl（该模板没有默认版本，需自行创建）；[next-dev] 已移除整条特性，该键既不生成也不被读取。
    • reloadDelay：master / next 生成并生效（连上实现端后延迟加载好友/群/群员信息）；[next-dev] 起已无此键。
    • twitter.cfclearance：三个分支都没有这个配置键，也没有读取点；代码只在抓取时识别 Cloudflare 拦截并报错，无法通过配置注入。
    • weibo.alertGroupId / weibo.alertQQList：getter 均无调用者，[next-dev] 已不再生成这两个键，设置无效；告警目标改由 /config weibo_alert 控制。
    • acfun.minFollowerCap：代码没有任何读取点，[next-dev] 已不再生成该键，设置无效。
    • douyu.interval / huya.interval：[next-dev] 生成该键且已生效（轮询间隔取 site.interval，未配置时回退 concern.emitInterval，再缺失用内置 5s）。master / next 不生成也不读取该键，斗鱼/虎牙轮询走全局 concern.emitInterval。

    字段分类速查

    按功能模块分类，点击进入详细说明：

    模块 关键字段 说明
    bot 与连接 bot.*、websocket.*、debug、message-marker、qq-logs、adapter.*（[next-dev]） 账号、命令前缀、掉线策略、OneBot/适配器连接、调试
    B 站 bilibili.* cookie/扫码登录、检测间隔、图片合并、关注策略、专栏解析
    推特 twitter.* nitter 镜像、UA（master）；api 模式、自动翻译（[next-dev]）
    抖音 douyin.* cookie/UA、人机验证、live（WSa 新增，测试）；news 与 sessionId（[next]）
    其它订阅源 acfun.*、weibo.*、youtube.*、douyu.*、huya.*、twitcasting.* A 站/微博/YouTube/斗鱼/虎牙/TwitCasting；小红书/Twitch/小黑盒为 [next-dev]
    代理与图片池 proxy.*、localProxyPool.*、pyProxyPool.*、imagePool.*、localPool.*、loliconPool.* 代理池、图库
    推送与模板开关 concern.*、dispatch.*、notify.*、template.*、autoreply.*、cronjob.*、customCommandPrefix 推送调度、模板、自定义命令、定时消息
    Web 管理面板 admin.*、platform.<site>.enable 面板启停与地址（[next-dev]）；按平台停用轮询 / 推送

    最小可用配置

    如果只想快速跑起来测试，下面这份就够：

    bot:
  onJoinGroup:
    rename: "【bot】"

bilibili:
  qrlogin: true
  interval: 25s

concern:
  emitInterval: 5s

template:
  enable: true

websocket:
  mode: ws-server
  ws-server: 0.0.0.0:15630

logLevel: info

    不配置 B 站账号时，订阅数不要超过 5 个，否则推送延迟上升；配置 B 站账号后代码日志称最高可支持 2000 订阅。

    Web 管理面板（admin，[next-dev]）

    [next-dev] 内置 Web 管理面板，默认关闭：

    admin:
  enable: false              # 默认 false；不开则完全不启动管理服务
  addr: "127.0.0.1:15631"    # 监听地址，默认仅本机可访问
  token: ""                  # 访问密码；留空时首次打开进入初始化向导
    字段 默认 说明
    admin.enable false 是否启动 Web 管理面板。关闭时不会监听任何端口
    admin.addr 127.0.0.1:15631 面板监听地址。默认仅本机可访问
    admin.token 空 面板登录密码。留空时所有数据接口返回 401，只能进入初始化向导

    admin 配置修改后需重启；只有初始化向导写入的 admin.token 会在运行期热生效。详见 Web 管理面板。

    面板默认只监听本机

    不要把面板直接暴露到公网。确需远程访问时用反向代理加 HTTPS，并设置足够强的密码。

    平台级启停（platform，[next-dev]）

    [next-dev] 可以按平台单独停用轮询与推送：

    platform:
  weibo:
    enable: false            # 停用微博；缺省或 true 视为启用
    取值 行为
    缺省 / true 平台正常轮询与推送
    false 停止该平台的 API 请求与推送；已有订阅数据保留，改回 true 即继续

    site 用订阅源标识（如 bilibili、weibo、twitter、douyin、acfun、twitch）。该开关走配置热重载，无需重启。

    配置热重载

    DDBOT 用 viper 的 WatchConfig 监听配置文件变化，以下配置修改后无需重启：

    • customCommandPrefix（自定义命令前缀）
    • cronjob（定时消息）
    • platform.<site>.enable（平台级启停，[next-dev]）

    bot.commandPrefix、debug.* 等每次读取配置的键也会即时生效；其余多数配置项修改后需要重启 DDBOT。
